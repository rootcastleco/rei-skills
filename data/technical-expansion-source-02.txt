# REI original skill expansion — technical briefs 02/05
@embedded-rtos|Embedded RTOS Engineering|development|critical|task schedules, ISR traces, MCU reference manuals, peripheral timing logs and RTOS configuration|microseconds, hertz, bytes and CPU percent|measured worst-case execution traces and platform-specific scheduler specification|priority inversion, ISR starvation and watchdog expiry|Do not change live machine firmware or safety control loops without isolated hardware validation.
priority-inversion-analysis: Identify shared mutex ceilings and blocked high-priority paths under representative task contention.
wcet-scheduling-budget: Bound worst-case execution times and blocking delays against hard task deadlines.
interrupt-latency-profiling: Measure ISR entry, nesting and completion latency using a traceable logic analyzer reference.
dma-buffer-ownership: Define cache coherency and ownership transfer between DMA engines and application tasks.
rtos-tickless-idle: Estimate sleep savings without breaking timer deadlines or tick compensation correctness.
watchdog-supervision-tree: Distinguish stalled task, scheduler and hardware watchdog failure recovery paths.
stack-watermark-audit: Measure task stack high-water marks under exception, nested interrupt and stress conditions.
deadline-miss-telemetry: Record execution overruns with bounded diagnostics and no blocking I/O in critical paths.
mutex-deadlock-triage: Reconstruct lock acquisition order and test cyclic wait detection under fault injection.
peripheral-isr-splitting: Move slow processing out of ISRs without losing sample-order or deadline semantics.
rtos-message-queue-bounds: Choose queue capacities and overflow policies from sensor burst rate and consumer latency.
scheduler-mode-transition: Validate mode changes during boot, degraded operation and safe shutdown without race windows.
memory-fragmentation-budget: Bound dynamic allocation churn after initialization and document deterministic fallback.
clock-domain-transition: Verify peripheral baud and scheduler timers after dynamic frequency or low-power transitions.
brownout-recovery-state: Preserve recoverable state after supply droop without trusting partially committed flash records.
fault-handler-snapshot: Capture minimal crash context with register provenance without recursive failure or unsafe flash writes.

ab-slot-state-machine: Define active, pending, confirmed and rollback slot transitions with atomic metadata writes.
power-loss-injection: Test interruption after each critical flash phase and prove a recoverable boot path.
anti-rollback-versioning: Enforce monotonic security version counters without blocking authorized factory recovery.
delta-update-integrity: Verify reconstructed binary hashes and bounds before switching execution images.
boot-health-commit: Commit new image only after bounded runtime self-test and explicit health confirmation.
secure-key-rotation: Rotate image-verification trust anchors with overlapping signed update windows and revocation plan.
flash-wear-budgeting: Count erase cycles and metadata transaction rates against the selected memory endurance evidence.
encrypted-image-storage: Separate confidentiality keys from signature trust and test decryption failure handling.
update-resume-offset: Validate persisted download offsets with chunk hashes to avoid mixed-image restarts.
manifest-schema-compatibility: Reject incompatible hardware revisions and unknown mandatory manifest fields before download.
update-bandwidth-throttle: Schedule firmware transfers around real-time telemetry and energy-budget constraints.
bootloader-recovery-console: Define authenticated maintenance access without exposing raw flash writes to unauthenticated users.
fleet-rollout-canary: Use staged cohorts and automatic stop conditions based on boot success and regression indicators.
firmware-bom-traceability: Link SBOM, compile flags, signing operation and reproducible image hash for each release.
ota-revocation-drill: Exercise revoked certificate and compromised-version scenarios without disabling secure boot safeguards.

diagnostic-port-lockdown: Verify debug interfaces are disabled or authenticated on shipped builds with recovery controls documented.
secure-boot-measurement: Verify firmware chain-of-trust evidence across boot stages and mutable partition boundaries.
provisioning-supply-chain: Design auditable manufacturing key injection and secure handling of rejected units.
cloud-policy-least-privilege: Constrain each device API identity to its own topics, resources and command scopes.
tamper-event-handling: Distinguish physical tamper telemetry from security incident proof and avoid false claims.
network-segmentation-map: Document device-to-broker trust boundaries, egress allowlists and management-zone separation.

firmware-component-inventory: Map firmware dependencies to component versions and actionable vulnerability assessment evidence.
disconnected-auth-expiry: Define limited offline authorization validity and revocation reconciliation after reconnect.
incident-key-containment: Revoke affected device identities while maintaining unaffected fleet availability and forensic evidence.
